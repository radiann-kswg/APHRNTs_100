# Claude作業ログからの創作進捗 自動記録機能（4ソース版）

> Claude Desktop の推奨機能。**4つの情報ソース**——①Claudeセッション履歴（`session_info`）、②GitHub更新記録（GitHubコネクタ）、③Dropbox更新履歴（Dropboxコネクタ）、④Misskey Bot記録（`logs/bot-digest.md`）——を振り返り、その日に取り組んだ創作活動の進捗と作業内容を、生活管理ログ `logs/YYYY-MM-DD.md` へ半自動で記録する。センパイが手で書かなくても、Claude外で行った作業（手元での直接コミット・イラスト制作・Misskeyでの報告）も含めて継続的に記録できるようにするのが狙い。

共通仕様の正典は [AGENTS.md](../AGENTS.md)、ログ記録フォーマットの正典は [logs/README.md](../logs/README.md)。本ドキュメントはその上に乗る「Claude固有の自動記録運用」を定義する。

## 背景と目的

近ごろの創作作業の多くは Claude Desktop 上で行われている（VRMモデル制作、CreationsDB/CreationsAI のデータ整備、キャラ画像生成、リポジトリ保守 など）。これらは各セッションの履歴として残っているため、`session_info` ツールで読み返せば、「何に取り組み・どこまで進んだか」を機械的に振り返って記録に起こせる。

対象とするのは [logs/README.md](../logs/README.md) の推奨フォーマットのうち次の2欄のみ：

- **創作活動の進捗** … ナンバーテールズ／百花繚乱研究所の創作に直接関わる進捗。
- **取り組んだタスク** … それ以外の Claude Desktop 全般の作業（他プロジェクトの相談・調べ物・環境設定・再就職活動 等）。

体調・気分・睡眠・思考記録などの**機微な健康情報はこの機能では一切扱わない**。それらはセンパイ本人／Health Sheet が書く欄であり、自動記録の対象外とする。

## 仕組み

1. 実行日の**前日**を対象日 `YYYY-MM-DD` とする。
2. **4ソースから対象日の活動を収集する**（タイムスタンプは全ソースともJST基準で判定。GitHub・DropboxはUTC+9換算）:
   - **①Claudeセッション**: `session_info` の `list_sessions` / `read_transcript` で対象日のセッションを特定し、各作業を1〜2文で要約（事実のみ、推測で盛らない）。
   - **②GitHub**: GitHubコネクタ（読み取り専用）で百花繚乱研究所4リポジトリ（CreationsDB／CreationsAI／GeneratorsAI／NumberTales-MisskeyAIBot）の当日コミット・PR・Issueを収集。CIボットの自動sync系コミットは1行に集約。
   - **③Dropbox**: Dropboxコネクタ（読み取り専用）で当日更新ファイルを収集。**主対象は「Creative Cloud Files」**（創作進捗の大半のデータがここにある・2026-08-06センパイ指示）。確認するのは**メタデータのみ**（パス・ファイル名・server_modified・サイズ）で、ファイルの中身は開かない。補助対象（「生成AI成果物」「友人制作」「素材」「日誌など」）は、主対象と他ソースだけでは当日の手がかりが薄い場合にのみ軽く走査する。イラストPSD/PNG・フォント素材・入稿データ・3Dモデル等は創作の有力な証跡。「Visual Studio Code Backups」の自動バックアップは原則除外（他に手がかりが無い日のみ「開発作業の裏付け」として1行集約可）。同日多数更新は「○○フォルダで12点更新」のように要約。
   - **④Misskey**: `logs/bot-digest.md` の「日次チェックイン」から対象日の創作メモ（`創作: ...`）を取り込む（センパイ本人の報告なので内容を変えない）。
3. 各項目を「創作活動の進捗」「取り組んだタスク」に振り分ける。複数ソースが同じ作業を指す場合は1項目にまとめ、末尾タグ（［セッションタイトル］［GitHub］［Dropbox］［Misskeyチェックイン］［センパイ本人の記録］）を併記する。
4. `logs/YYYY-MM-DD.md` の **creative-log マーカー区間だけ**を編集する。区間内の ［センパイ本人の記録］／［Misskeyチェックイン］ タグ付き項目は本人由来の記録なので、置換時も必ず維持する。

### creative-log マーカー

自動記録は、次のマーカーで囲まれた区間だけを対象にする（Health Sheet の `health-sheet` マーカーと同じ設計思想）。

```markdown
<!-- creative-log:start -->

## 創作活動の進捗

- 〜〜〜。［セッションタイトル］

## 取り組んだタスク

- 〜〜〜。［セッションタイトル］

<!-- creative-log:end -->
```

- マーカー区間が既にあれば、その中身だけを新しい内容で**置換**する（冪等・重複しない）。
- マーカーが無い既存ファイルには、`## 100(モモ)からのひとこと` 見出しがあればその**直前**に、無ければ**末尾**にマーカー付きで挿入する。
- ファイルが存在しなければ新規作成する（先頭に `# YYYY-MM-DD` 見出し。体調・気分・睡眠の欄は作らない）。
- 対象日に該当セッションが無ければ各欄に「（該当なし）」と書く。

### 安全則（厳守）

- `<!-- health-sheet:start -->` 〜 `<!-- health-sheet:end -->` の区間、およびセンパイの手書き内容（体調・気分・睡眠・思考記録・トピック・夜の追記・ひとこと 等）には**絶対に触れない**。
- 編集対象は `creative-log` マーカー区間のみ。
- `logs/*.md` は機微情報を含むためリポジトリ管理外（[.gitignore](../.gitignore)）。本機能はローカルファイルだけを編集し、コミットやpushは行わない。

## 運用（日次スケジュールタスク）

Claude Desktop の「Scheduled」機能に、前日ぶんをまとめる日次タスクを登録して運用する。

- タスクID: `momo-creative-log-daily`
- スケジュール: 毎日 07:30 頃（前日の作業を翌朝にまとめる。時刻はセンパイの生活リズムに合わせて調整可）
- 実体: `C:\Users\<user>\Claude\Scheduled\momo-creative-log-daily\SKILL.md`
- 動作: 上記「仕組み」の1〜4を実行し、100(モモ) の口調で要点を報告する。GitHub／Dropboxコネクタが未認証・エラーの場合は該当ソースだけスキップして続行し、報告時にその旨を添える。
- 2026-08-05更新: GitHub・Dropbox・Misskeyを加えた4ソース版へ拡張（それまではセッション＋GitHubの2ソース）。
- 2026-08-06更新: Dropbox走査を「Creative Cloud Files」主対象・メタデータのみ確認へ変更（センパイ指示）。他フォルダは補助扱いとし、7/9〜8/5分の再照合で7/25・7/29・8/1の記載を補正済み。

スケジュールタスクはアプリ起動中に実行される。起動していない時刻に予定が来た場合は次回起動時に実行される。

### 手動での実行

任意のセッションで「昨日の創作進捗を記録して」「ここ数日の作業を棚卸しして」等と頼めば、同じ手順を手動で走らせられる。過去日をまとめて棚卸しする場合、古いセッションは `list_sessions` の取得上限から外れて拾えないことがある（その旨を注記する）。
